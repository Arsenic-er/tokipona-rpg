# 森林第一章美术与像素物理设计规格

- 状态：用户已批准的架构设计 v0.1
- 日期：2026-08-29
- 适用范围：森林第一章《水往何处》的正式视觉重构与第一阶段像素物理
- 关联章节规格：[森林第一章《水往何处》设计规格](./2026-08-28-forest-chapter-design.md)

本规格把美术生产放在第一章实施顺序的最前面，并定义可见像素、后台区块、昼夜、光照、角色动画、材质反应、重力、破坏、存档和性能之间的边界。它保留已经完成的章节、任务、学习、经济、生态、声望和跨存档逻辑；视觉与物理重构不得以重写或删除既有逻辑为代价。

本规格取代旧世界尺度原型中“16 px 可见地块、窄屏审计布局、角色发光、程序占位人物”的视觉方向。旧原型仍可作为技术与概念记录，但不能作为正式美术验收标准。

## 1. 目标与约束

第一章要建立一种“小人物面对大环境”的横版像素世界：角色很小，森林、遗迹、水利设施和地貌占据画面主体；近景材料能够以 1 px 颗粒流动、燃烧、堆积和破坏；远景保持手工构图和稳定的美术层次。

必须同时满足以下目标：

1. 正式游戏画面全屏显示，不再把大面积永久让给审计面板；
2. 基准逻辑视野为 `640×360`，固定纵向视野，宽屏横向扩展；
3. 可交互材料以 1 逻辑像素为最小单元，不能继续显示为明显的 16 px 大方砖；
4. 角色视觉高度约 20 逻辑像素，无发光轮廓、无胖圆或 Q 版比例；
5. 同一批场景素材可覆盖清晨、白天、黄昏、夜晚及以后加入的天气和异常状态；
6. 第一章实现有限但真实的材质组合、质量守恒水流、基础重力和局部受控力场；
7. Windows 目标 60 fps，Android 使用相同物理规则并支持 60/30 fps 自适应；
8. 已提交的剧情和环境结果必须保留，未提交的软锁破坏必须可恢复。

## 2. 选择的总体路线

采用“分层系统化垂直切片”，而不是完整复制《Noita》的通用模拟，也不是传统瓦片地图加假粒子。

- 活跃水、沙、土、泥、烟、蒸汽、薄冰和碎屑以 1 px 单元运行；
- 后台用不可见的 `16×16` 活动区块管理更新、存储和休眠；
- 建筑、机关、角色和大型地标使用审阅过的像素资产；
- 只有标记为可反应的区域进入像素物理，关键结构和主线路径受保护；
- 渲染层表现结果，但不能自行生成任务、学习或存档事实。

未来可以逐区域扩展到更高精度流体、更多化学反应和任意方向重力。本阶段不承担完整通用物理沙盒。

## 3. 美术圣经

### 3.1 视觉身份

- 主体：深绿森林、潮湿岩石、老木材、苔藓与浅水；
- 文明痕迹：克制使用氧化铜、旧石构件与古代水利装置；
- 辅助色：青绿色水光和反射；
- 强调色：琥珀色只用于罕见异常、媒介反应和关键视觉焦点；
- 禁止：角色常驻光环、大片均匀霓虹、粗大假粒子、显眼重复方砖和覆盖玩法层的高对比背景。

选定的统一视觉概念图保存在私有素材仓，只作为构图和色彩参考：

`source/art/concepts/forest-chapter/waterwheel-unified-visual-target.v001.png`

概念图不是运行时素材，不得绕过人工审阅、许可、哈希和导出流程进入公开仓。

### 3.2 角色

- 视觉高度约 20 px，采用小而修长的人类旅行者轮廓；
- 初版仍是可替换占位角色，但质量要足以审计比例、动画和构图；
- 身体、肤色、头发、服装、配饰分层，为以后玩家自定义、多起源和多种族预留；
- 动画采用 8–12 fps 手绘关键帧；
- 第一批状态包括待机、行走、奔跑、起跳、上升、下落、落地、抓边、短攀爬、浅水行走、受击、倒地、持物、近战、瞄准、施法准备、释放和中断；
- 头发、披风和小挂件可以有轻量物理延迟，但不参与碰撞和伤害；
- 视觉动画与碰撞体分离。第一轮接入保留现有 `12×14` 碰撞体，除非后续移动验收以独立规格批准变更。

### 3.3 景深与镜头

画面使用四层景深：

1. 可交互前景：角色、机关、战斗、1 px 材质和权威地形；
2. 近景：树干、灌木、建筑、遗迹主体；
3. 中远景：森林轮廓、山体、聚落和大型遗迹；
4. 天空雾层：云、雾、降雨和极弱异常色光。

背景逐层降低对比度和饱和度，不得遮住角色、互动点或活跃材料。镜头采用死区跟随，按朝向留出前方空间；接近悬崖、地标和大型机关时缓慢偏移。正常游玩不持续缩放，镜头必须保持像素对齐。震屏只响应明确冲击，具有强度上限和无障碍开关。

### 3.4 全屏与设备比例

- 基准逻辑视野为 `640×360`；
- 逻辑高度固定为 360 px，16:9 至少显示 640 px 宽；
- 超宽屏和横屏手机增加左右可见环境，不放大人物；
- 世界渲染采用整数倍像素缩放，不拉伸像素；
- UI 使用设备安全区，缩放 UI 不改变世界像素密度；
- 审计、任务详情和调试信息收进可开关菜单，默认不占据右侧常驻栏。

### 3.5 地点身份与复用

第一章共用土、木、岩、水、植被和遗迹基础材质。每个地点增加约 20%–30% 的独特轮廓、地形模块、建筑和玩法材质：

| 地点 | 独特美术身份 |
|---|---|
| 到达山脊 | 裸岩、树根、远山、冷晨雾 |
| 溪流旧路与隐士居所 | 密林、浅溪、朽木、旧石标记 |
| 边境聚落 | 木屋、石基、耕地、生活灯火 |
| 水轮峡谷 | 大型木结构、苔藓、氧化铜、青绿水光 |
| 高位蓄水池 | 冷石、竖井、铜管、水汽和高差 |
| 回流湿地 | 芦苇、泥、水洼、兽迹和低雾 |
| 地下秩序节点 | 岩层、古代装置、克制的琥珀与青绿异常 |
| 可选巢穴洞窟 | 干土、根系、幼体痕迹 |
| 可选安全训练场 | 受控木、石、沙和材料靶 |

资产组合的项目目标约为 65% 通用基础素材、20% 状态与覆盖素材、15% 地点专属地标。这是制作预算指导，不是要求每张地图机械达到同一比例。

## 4. 昼夜、光照和状态复用

### 4.1 昼夜周期

完整昼夜为 48 分钟：

- 清晨 6 分钟；
- 白天 20 分钟；
- 黄昏 6 分钟；
- 夜晚 16 分钟。

玩家可以通过睡眠、旅店或安全营地推进时间。切换地图、存档和重载不得重置世界时间。主线不得要求玩家原地等待特定时段，关闭的服务和时段限定路线必须提供休息、替代入口或次日推进方式。

昼夜影响怪物组合、动物活动、NPC 作息、商店、局部温度、能见度、灯火价值、环境音和少量采集物，但不能让低性能设备获得不同的权威结果。

### 4.2 光照

采用“烘焙氛围 + 局部动态光”：

- 场景基础色、明暗关系和构图由美术控制；
- 清晨、白天、黄昏、夜晚分别使用环境光曲线、LUT、天空色和雾色，并连续插值；
- 火焰、灯具、魔法、水面反射和闪电提供像素级局部动态光；
- 素材可以附带高度、受光或法线信息，但不能破坏像素边缘；
- 动态光不得成为角色常驻描边。

天气和世界异常使用独立覆盖层和强度遮罩。第一章先建立接口，具体天气种类、概率和特殊状态另行设计，不在本规格中猜测。

## 5. 像素物理合同

### 5.1 材料和状态

第一批材料：

- 固体：土、岩石、木材、金属、薄冰、灰烬；
- 粉体：沙、松土、碎屑；
- 液体：水、泥浆；
- 气体：烟、蒸汽；
- 能量状态：温度、燃烧、冷却、冲击。

第一批有限反应：

- 水 + 土 → 泥；
- 火 + 木 → 烟、焦化、灰烬；
- 水 + 高温 → 蒸汽；
- 水 + 低温 → 薄冰；
- 强水流搬运沙、松土和轻型碎屑。

材料反应遵守预先定义的质量和能量收支，不能凭空生成材料。第一章不做自由组合化学，但反应目录必须可扩展。

### 5.2 水流

- 水量守恒；
- 使用近似压力完成填坑、漫溢、连通和分流；
- 水源、排水口和任务水量由权威地图或事件定义；
- 不在第一章实现完整 Navier–Stokes、持续涡流或任意流体混合；
- 架构保留高精度流体适配接口，升级不得改变已提交存档语义。

### 5.3 重力和局部力场

- 正常区域使用统一向下基础重力；
- 角色、刚体、粉体、液滴和碎屑共享同一重力基准；
- 材料定义密度、浮力、空气阻力、终端速度和稳定堆积角；
- 木材、尸体和轻型物体可浮起，重物下沉，烟和蒸汽上升；
- 超过稳定角的颗粒滑落，受支持结构破坏后可以局部坍塌；
- 古代媒介、失衡区域和特定法术可以创建有限范围、有限持续时间、具有能量来源的增重、减重、吸引或排斥场；
- 第一章不支持把墙壁或天花板变成永久地面。任意方向重力留给后续特殊区域。

### 5.4 破坏与任务保护

普通土层、腐木、树根、薄岩和明确标记的建筑构件可以被挖掘、燃烧或冲击破坏。关键建筑、主线机关和必要通路具有结构保护，但仍显示裂纹、焦化、漏水、火星和碎屑。

保护规则必须来自权威场景数据，渲染器和特效不能自行判定。对保护结构的超额能量仍可以转化为受控反馈，但不能悄悄破坏任务状态。

### 5.5 角色运动

- 移动追求即时响应并保留轻微重量感；
- 地面水平移动采用两段加速：先快速达到步行速度，再较慢积累到跑速；满幅键盘输入不得首帧进入跑步动画；
- 水平输入保留 `-1…1` 的模拟强度，键盘和方向按钮使用满幅值，未来虚拟摇杆轻推可以稳定停留在步行速度；
- 走路与跑步使用不同动作循环，动画状态由真实水平速度投影，不能把跑步动画简单降速冒充走路；
- 当前步态候选将走路与跑步帧均保持 `5 tick`（约 `12 FPS`），并在约 `74 px/s` 后进入跑步表现，保证接触、承重、交叉与换脚姿势可被看见；
- 支持空中方向修正、抓边、短攀爬和浅水阻力；
- 跳跃、坠落伤害、击退和攀爬统一读取重力参数；
- 动画不改变碰撞体；
- 以后魔法改变速度、重量或方向力时，必须通过统一物理命令，不能由 VFX 或 UI 直接写物理状态。

## 6. 运行时边界与数据流

建议把系统分为以下独立单元：

1. **地图与结构投影**：读取已验证场景、碰撞、任务保护和地点身份；
2. **材料世界**：维护 1 px 活跃单元、`16×16` 区块、脏区域、休眠与恢复；
3. **反应目录**：纯数据定义材料、状态转换、质量和能量收支；
4. **重力场服务**：计算基础重力和受权威命令约束的局部力场；
5. **视觉投影**：把物理和 GameSession 状态转换为背景、素材状态、粒子和灯光，不提交领域事件；
6. **环境提交桥**：只有经过验证的任务或物理终态可以通过它写入永久环境结果；
7. **资产包读取器**：只接受公开仓中带版本、哈希和许可状态的批准导出。

数据流必须保持单向：

```text
已验证内容与 GameSession
→ 地图/物理权威状态
→ 物理步进与终态验证
→ 可选的环境领域提交
→ 窄视觉投影
→ 全屏渲染
```

渲染、UI、天气粒子和背景动画不能反向生成任务完成、学习证据、MP、伤害或存档结果。

## 7. 存档、恢复与错误处理

永久保存：任务修复、渠道改造、闸门状态、关键建筑损伤、永久生态结果和已提交局部重力装置状态。

区域运行状态：活动物理区、积水、泥沙、火焰、烟、碎屑和临时力场。稳定且远离玩家的区块压缩休眠，重新进入时确定性恢复。

检查点恢复：清除未提交的软锁水、泥、火、碎屑、临时破坏和力场，同时保留已经提交的剧情与环境结果。

失败关闭规则：

- 未知材料或非法状态转换不执行；
- 质量或能量账不平的反应拒绝提交；
- 非有限、越界或无来源的重力场拒绝创建；
- 损坏区块不得静默替换为空，应隔离并回到最近有效检查点；
- 低画质和低帧率不得改变物理终态；
- 私有素材缺失不得由公开运行时路径回退读取开发机文件。

## 8. 性能合同

- Windows 目标 60 fps；
- Android 优先 60 fps，不能稳定时降为 30 fps；
- 物理使用固定步长，渲染帧率只影响插值；
- 只更新玩家附近、正在移动、燃烧、受热或发生反应的脏区域；
- 允许按设备降低活动模拟半径、背景装饰、雾、反射、阴影和非交互粒子；
- 不允许降低任务机关、反应公式、质量守恒或存档精度；
- 性能测试必须分别记录物理步耗时、活跃像素数、脏区块数、渲染耗时和内存，而不是只记录总 fps。

## 9. 素材仓和公开仓边界

- 概念图、源工程、未审批贴图、动画源文件和音频保存在私有素材仓；
- 通过人工视觉、许可、哈希和平台检查后，生成版本化运行时导出；
- 公开仓只接收批准后的导出文件和机器清单；
- 公开构建不能依赖私有仓路径或开发机绝对路径；
- 概念图必须保持 `runtimeReady=false` 或等价阻断状态，不能冒充正式资产；
- 以后玩家自定义部件也必须走同一像素密度、锚点、动画和许可检查。

## 10. 美术优先实施顺序

### 阶段 1：统一视觉样板

只制作一个森林—水车可玩样板：全屏、约 20 px 角色、四层景深、死区镜头、正式比例、四个昼夜阶段和局部动态光。天气和世界异常只保留接口。该样板未通过用户视觉审计前，不批量制作其他地点。

### 阶段 2：第一章通用素材库

制作基础土、木、岩、水、植被、遗迹构件，以及潮湿、裂纹、焦化和积灰遮罩；完成第一批角色动画与自定义分层规范。所有候选先进入私有素材仓。

### 阶段 3：1 px 物理与重力样板

在同一场景接入水流、沙土、泥、烟、蒸汽、薄冰、火与木材、浮力、坠落、堆积、分层破坏和局部受控力场，并建立 Windows/Android 性能剖析。

### 阶段 4：地点化生产

按共用素材库依次完成山脊、旧路与隐士居所、聚落、水车、蓄水池、湿地和地下节点，再处理可选洞穴和训练场。每张地图必须通过轮廓、地标和玩法材质形成独立身份，不能只换 LUT。

### 阶段 5：接回第一章逻辑

把已有任务、道本语学习、贸易、声望、生态、昼夜活动、存档和区域流接到新的表现与物理层。既有领域状态继续是权威；视觉重构不得建立第二套平行任务逻辑。

## 11. 测试和验收

### 11.1 视觉验收

1. 游戏世界占据完整主画面，审计控件默认收起；
2. 人物与世界比例符合选定概念方向，无胖圆比例和常驻发光；
3. 活跃材料颗粒为 1 px，不出现可见的 16 px 假粒子；
4. 同一水车场景的清晨、白天、黄昏和夜晚明显不同，但没有复制四套基础建筑；
5. 四层景深和镜头偏移不遮挡角色、互动点或材料反应；
6. 宽屏显示更多左右环境，人物和颗粒大小不变。

### 11.2 物理验收

1. 水量守恒，填坑、漫溢和分流结果可重放；
2. 五类首批反应满足材料与能量账；
3. 浮力、下沉、烟汽上升、堆积和坍塌符合材质参数；
4. 远离玩家的稳定区块休眠，返回后状态一致；
5. 30 fps 和 60 fps 输入回放产生相同权威终态；
6. 受保护结构只产生受控反馈，不破坏任务；
7. 检查点删除未提交软锁，保留已提交环境结果。

### 11.3 集成验收

1. 第一章现有内容、类型、单元、集成、存档和构建门保持通过；
2. 旧存档迁移不能重置昼夜或已提交结果；
3. 昼夜改变生态和作息时，主线仍始终可推进；
4. 公开构建只使用批准素材导出；
5. Windows 视觉样板达到目标 60 fps；Android 在同一物理回放下达到 60 或稳定 30 fps。

## 12. 非目标

- 第一章不实现开放式化学、完整流体方程或全世界任意方向重力；
- 不在本规格中决定所有天气、异常群落和后续地区的视觉状态；
- 不制作最终所有种族、起源、服装和角色自定义内容，只建立兼容结构；
- 不把概念图直接当作正式运行时贴图；
- 不重写已经完成的第一章领域逻辑；
- 不声称已经完成正式美术、移动端优化或全部第一章地图。

## 13. 技术参考原则

参考成熟作品的工程方法，但不复制其资产、世界、角色或具体关卡：

- 《Noita》：以活动区块和脏区域限制逐像素模拟成本；
- 《Graveyard Keeper》：用环境光、LUT、动态灯光、雾和风复用基础像素素材；
- 《Eastward》：按自然结构拆分素材，并使用光照信息和天气系统增强同一资产；
- 《Rain World》：用遮罩局部重染或替换环境，同时保护角色可读性。

这些参考只说明可采用的工程模式。本项目的森林文明、道本语媒介、世界平衡失效、角色、地标和具体视觉语言必须独立设计。

# 森林开场最小完整切片设计规格

- 状态：用户已批准的架构设计 v0.1
- 日期：2026-08-31
- 范围：森林入口 → 浅溪 → 聚落外围的 10–15 分钟正式垂直切片
- 依赖：[2026-08-28 森林第一章设计](./2026-08-28-forest-chapter-design.md)、[2026-08-29 美术与像素物理](./2026-08-29-forest-chapter-art-physics-design.md)、[2026-08-30 连续森林与生态](./2026-08-30-forest-continuous-map-ecology-design.md)

## 1. 目标

把已通过的连续森林技术灰盒升级为第一个真正可评价的游戏片段。玩家应能在不看开发面板、不使用传送、不杀生、不提前施法的前提下，从森林边缘抵达聚落外围。

本切片要同时证明：

1. 小人物与大环境的比例和画面纵深成立；
2. 人物动画、声音、生态和环境交互形成完整玩法节拍；
3. 手工模块化像素美术与局部 `1 px` 材料反应可共存；
4. 已有第一章任务、学习、检查点和存档仍是唯一领域权威；
5. Windows 键盘和 Android 横屏触控均能完整通过。

这不是第一章全部内容，也不是通用逐像素物理引擎的完成版。

## 2. 玩家体验流程

### 2.1 森林苏醒（1–2 分钟）

人类旅行者在清晨冷雾中醒来。玩家只知道自己是外来者，身份与起源保持未知。画面通过行囊、旧路遗迹和一次轻微、无法解释的物理异常建立背景，不使用长段旁白。

### 2.2 浅溪林地（约 3 分钟）

玩家在真实地形中学会移动、跳跃和浅水行走。一只兔子在林间觅食，听见玩家后逃向灌木；一只湿地鸟在水边短暂停留后飞离。昆虫活动、草叶扰动和水面涟漪作为抽象生物量表现，不生成大量可碰撞小生物。

### 2.3 被冲坏的旧路（4–6 分钟）

旧导水槽旁的路面已被溪水冲坏。玩家有三类合法方案：

- 搬动两块松石形成落脚点；
- 拖动一段朽木搭路；
- 从浅水和软土下方绕行。

水能推动轻型碎屑，松土遇水变泥。这是有限反应目录，不扩展为通用化学或高精度流体。

旧导水槽和石标上反复出现 `telo` 象形符号。玩家可观察、触摸和记录，但不得知道读音、中文释义或施法方法。

### 2.4 设施劳动者（约 2 分钟）

一名聚落设施劳动者根据玩家的解决方式给出简短反应。NPC 不把玩家当成预言中的拯救者，只认可其愿意帮忙或有能力自救。对话使用中文文本与像素风“嘟嘟”声，不制作完整语音。

### 2.5 聚落外围（约 2 分钟）

镜头逐步展示森林开阔草地上的聚落、炊烟、水渠和居民活动。玩家获得外围安全检查点。切片以三个未解问题结束：水边符号是什么、旧设施为何失修、旅行者为何能感觉到异常。

切片不进入聚落完整任务、贸易、战斗或法术教学。

## 3. 视觉与角色

### 3.1 画面

- 使用 `640×360` 基准逻辑视野并全屏显示；逻辑高度固定为 `360 px`，宽屏增加左右环境，不放大人物；
- 使用四层景深：雾化远林、中景树干与山体、近景遗迹与植被、可交互材料层；
- 地形轮廓由洞口、坡地、高树、溪沟和开阔草地组成，不使用平直平台串联；
- 不把 AI 生成的完整场景图直接当作地图。树根、岩壁、溪岸、朽木、水槽、草丛和聚落构件使用原创模块组合；
- 清晨自然过渡到晨间日光，复用同一套基础素材与局部光照数据。

### 3.2 默认旅行者

- 约 `20 px` 高、修长人类比例，无光环、无 Q 版大头或胖圆轮廓；
- 中性旅行斗篷、短靴和简洁背包，不锁定出身；
- 源素材把身体、肤色、头发、服装和配饰分层，为以后的多起源、多种族与玩家初始化预留；
- 首批动作：待机、步行、跑动、起跳、下落、落地、推拉、浅水行走、观察碑文；
- 保留已验证的 `12×14` 碰撞体，动画不修改碰撞和伤害。

## 4. 声音

最小声音集包含林风、叶片、溪水、远处鸟声、土/石/木/浅水脚步、石木碰撞、碎屑入水、角色动作和 NPC 对话嘟嘟声。

环境声以地区与距离混音，不循环播放一条不变的混合音轨。对话嘟声不对应真实道本语发音，不冒充语音教学。

## 5. 技术架构

### 5.1 正式入口

新增 `chapter-one.html` 作为正式切片入口。`world-scale.html` 保留为开发灰盒和空间回归门，不在玩家试玩导航中呈现。

### 5.2 领域权威

`PrologueFlowSession` / `GameSession` 继续保持剧情、检查点、学习伏笔、旧路结果和聚落抵达状态的唯一权威。不为垂直切片创建平行任务系统。

### 5.3 连续森林运行时

已验证的连续灰盒运行时升级后只负责：

- 玩家位置、重力、碰撞与相机；
- 手工宏观路线和浅溪局部材料口袋；
- 松石、朽木、轻碎屑、水、软土和泥的有限物理；
- 兔子与湿地鸟的感知、觅食、警觉、逃跑/飞离和栖息目标；
- 清晨到晨间的视觉时间投影。

它不能直接写入任务、学习、MP、声望或存档结果。

### 5.4 受信空间协调器

协调器把同一固定物理帧中的玩家位置、交互物状态、地区和世界修订号转换为现有语义提案。它仅允许提交：

- 符号观察/记录，但不产生词义或施法证据；
- 三种旧路解法之一的权威完成结果；
- 聚落外围入口与安全检查点。

渲染、UI 和浏览器事件不得直接传任务旗标、伪造位置或把玩家移动到目标。

### 5.5 表现层

表现层只读取窄视图：相机、角色动作、可见场景层、材料像素、生态动作、声音提示与最小 HUD。它不接收完整 `GameSessionState`、隐藏旗标、任务写入或伤害覆盖。

## 6. 存档与恢复

浏览器存档组合现有 `GameSessionSave` 与窄空间伴随状态，后者只包含位置、速度、检查点、旧路物体、活跃材料口袋、时间与生态个体状态。

- 已提交的旧路结果和聚落抵达来自 `GameSession`；
- 未提交的泥水、碎屑、物体偏移和生物受惊状态可在明确检查点恢复时重置；
- 页面后台化、`pagehide`、手动存档和跨地区检查点必须持久化组合封包；
- 损坏存档不回退成新档，而是显示可导出备份、恢复上一检查点或显式重建的页面。

## 7. 素材边界

- 候选角色、环境、动画、音效、提示图与源工程保存在私有素材仓；
- 候选素材必须产出场景对照图、动作表、循环声对照和实机录屏，由用户进行视觉/听觉审计；
- 只有审批、许可、无障碍和哈希均通过的版本可生成公开仓运行时导出；
- 公开构建不得读取私有仓、开发机绝对路径、概念图或未审批候选文件；
- 已拒绝的 v001–v003 水轮整景候选只保留为概念/错误历史，不复用为本切片背景。

素材未通过时，`chapter-one.html` 显示明确的“素材尚未批准”诊断。不允许静默回退到程序矩形灰盒并宣称是正式玩法。

## 8. 错误处理

- 空间快照包含非有限数值、未知地区或伪造交互时失败关闭；
- 素材缺失、哈希错误或未审批时不激活地区；
- 生态表不完整时阻止切片启动，不用无状态循环动画代替；
- 固定步进结果在 30/60 fps 下分叉时阻止发布；
- 缺失声音不改变权威结果，但发布门必须报错而不冒充完整切片。

## 9. 验收

### 9.1 玩法与叙事

1. 新档可在 10–15 分钟自然玩法量内抵达聚落外围；
2. 三种旧路解法均有效，无唯一正解、无传送；
3. 全程零击杀，不开放战斗或法术；
4. `telo` 只作为水环境中的未知符号出现，不授予词义、读音、学习证据或施法能力；
5. 设施劳动者反应解法差异，但不称呼玩家为救世主；
6. 抵达聚落后建立安全检查点和明确的后续悬念。

### 9.2 视觉与声音

1. 世界全屏显示，没有常驻调试面板或按钮墙；
2. 人物约 20 px、修长、无光环，桌面和移动端全程可见；
3. 四层景深和至少三类地形轮廓可明确辨识，角色、交互物和活跃材料不被遮挡；
4. 候选与运行时导出通过用户视觉审计、精确文件集和哈希门；
5. 地区环境声、材质脚步、物体交互和对话嘟声完整，静音模式不阻断进度。

### 9.3 技术

1. Windows 键盘与 Android 横屏触控均完整走通；
2. 保存、关闭页面、重开后继续，不复制旧路或聚落提交；
3. 30/60 fps 固定输入产生相同物理和生态结果；
4. 渲染/UI 不能写任务、学习、MP、声望或伤害；
5. 公开构建不包含私有仓路径、概念图或未审批素材；
6. 正式入口、素材门、存档、固定步进、桌面/移动 E2E、类型、内容、构建和 bundle 预算门全部通过；
7. 已知的 `forest-graybox-controller` 长路线 5 秒并发超时在新功能开发前被替换为稳定的可控成本验收，不简单放宽全局超时。

## 10. 非目标

- 不完成聚落内部、贸易、声望、水轮、隐士教学、安全训练场或第一章后半段；
- 不开放 `telo` 主动学习、媒介、MP 施法或攻击；
- 不实现通用流体、完整化学、任意破坏、完整生态食物网或动态天气；
- 不完成玩家初始化 UI、多种族或全部人物动作，只保证本切片的默认旅行者美术与数据可替换；
- 不复制 Noita、Rain World 或其他作品的素材、角色、关卡、具体配色或动画，只借鉴系统性材料和生态设计方法。

## 11. 实施顺序约束

1. 先修复已知基线长路线门的并发超时波动；
2. 再建立正式入口、切片状态与受信协调器；
3. 完成手工宏观构图、有限材料和三种旧路路径；
4. 完成角色、环境、生态与声音候选，在私有仓经用户审计后才导出；
5. 最后接入表现、存档、桌面/移动 E2E 和发布门。

任一阶段的中间产物只能标记为灰盒、候选或计划内实现，不得对用户称为“完整试玩”。

# 章节交付与验收约定

状态：2026-10-15 用户同意提案后开始实施。此文定义交付方法，不表示当前章节已通过。

## 唯一交付对象
以 chapter-one.html 实际运行的章节和对应最终 Windows 包为验收对象。
旧 rpg.html 的模型流程、时间预算和学习采样不能替代该入口的实测。
每次候选固定代码提交、私有素材版本、构建参数、文件哈希、平台与测试范围。
当前完整章节认证仍因 underground_handoff_required 阻塞；修复或对齐必须保留同等功能断言，禁止跳过断言、补造剧情标志或降低门槛使其变绿。

## 六个阶段
1. 范围确定：剧情起终点、地图、主支线、玩法、明确不做项及编号验收条目。
2. 美术与交互样板：先以实际场景确认角色、物件、阅读、操作和视觉风格，再批量制作。
3. 端到端可玩：普通输入贯通开局、推进、结算、保存和继续；检查点只用于局部回归。
4. 功能完整测试：需求映射测试，检查路线、资源、物理、输入、存档、平台与性能；保留失败证据。
5. 候选验收：冻结版本，测试最终包，在真实目标平台验证。用户集中验收艺术方向、可理解性和操作感受。
6. 通过与归档：用户确认结果，记录遗留项和延期原因；服务器保留证据、版本与回退条件。

## 每次交付卡
- 交付编号与状态：开发预览 / 待验收候选 / 已验收；三者不能混用。
- 构建身份：公开代码提交、私有素材清单及哈希、包哈希和测试环境。
- 范围：新增、变化、保持不变、未完成。
- 验收步骤：入口、前置存档、普通操作、预期结果、实测结果、证据路径。
- 测试汇总：通过、失败、未测、阻塞分别计数；局部测试不得称全仓通过。
- 已知缺陷：严重性、复现方式、影响、责任与处理状态。
- 更新说明：存档兼容、备份恢复、回退限制。
- 最终结论：由谁检查、何时检查、用户是否接受。开发者自测不是独立 QA。

## 测试矩阵
- 功能：剧情和分支、乱序探索、重复交付、失败与恢复、跨章继承。
- 规则：MP/物品消耗、一次性奖励、世界资源守恒、学习证据的真实取得。
- 物理：地形与碰撞一致、动物合法位置、水流与机关、暂停恢复。
- UI：键鼠与触控、焦点、连按、长文本、窗口/缩放、头像身份、气泡遮挡。
- 存档：新档/旧档、重启、中断、坏档保护、主档与实验室/临时旅程隔离。
- 包与平台：最终 EXE 离线启动和资源、完整流程、性能采样；Android 另测真实 APK 与设备。
- 人工试玩：不提示路线的首次游玩，记录卡点、实际时长和自然词义运用。模拟分钟数不代表真人三小时。

自动检查随改动运行；每个候选版本执行完整回归与最终包验证。
真实试玩在代表性切片和完整章节阶段进行，不强制新增考试。
需锁定目标设备后再确定性能预算，报告配置与帧时间分布，不凭短采样保证全程 60 FPS。
测试记录默认保存在服务器；原始玩家数据不进入公开仓。

## 放行条件
P0：崩溃、存档损坏、重大数据丢失，阻止正式验收。
P1：主线卡死、资源错误结算、关键输入/阅读不可用，阻止正式验收。
P2：不阻断流程的一般问题，可在明确披露并获用户同意后延期。
未测平台不计入通过。严禁用浏览器回归冒称 Windows/Android 原生验收。
真实玩家存档不用于自动测试。用隔离配置和测试存档。
仅在服务器开发/构建/测试；没有 Windows 测试环境时标记阻塞，不自动在用户本机执行。

- 工务人：独立像素头像与紧凑对话栏，保留原台词、确认和暂停。
- 木料架：非暂停玩家头顶反馈，镜头锚定，去重，离开收起，本次游玩可在 J 回看。

- 本轮不引入表情动画、打字机效果、新剧情或存档格式。

## 第二批实施边界：interaction-copy-01（2026-10-20）

- 范围：工务人、隐士首次教学与回访；维修到取得碎片、初次施法和交付的物品反馈；相关日志。
- 普通操作：木撑、支架、淤泥、闸门、石龛、木楔与休息可用气泡，游戏继续运行。学习选项、施法和不可逆决定仍保留明确面板。
- 角色台词不解释内部凭证、重复奖励防护或开发接入状态。实际费用、失败原因、必要路线与风险不能删除。
- 同一交互至少覆盖首次、重复、完成后及读档。核对提示与实际状态，特别检查空石龛、已休息、已交付时的回应。

- 地下复杂机关、其他角色画像、完整剧情与原生平台验收不包含在此批范围内。

# G-02｜咒语构筑：单词层数据库

状态：初稿 v0.5（逐词审阅中）  
审阅批次：`S1-04`  
更新：2026-08-06

## 1. 本轮边界

本轮定义首章候选的 14 个**单词咒语**：

```text
telo seli lete kiwen ko kon tawa kama pona pakala awen wawa suli lili
```

这里的“单词”指一个 toki pona 词项，不是一个拉丁字母，也不等同于一个 `sitelen pona` 图符。运行时主键使用拉丁词形；图符、字体和读音属于可替换的呈现资源。

除 `suli/lili` 的通用尺度适配契约外，本轮不定义逐字符串二词配方、简单句攻击或条件回路。后续组合只能引用本数据库中的语义钩子，不能反向篡改单词的语言说明。

本轮已确认的灰盒数值变更：

- `telo` 默认显化由 6 MP 调整为 **5 MP**；
- `tawa`、`kama`、`pakala`、`awen`、`wawa` 的单词语义共鸣费为 **1 MP**；
- `pona` 的单词语义共鸣费为 **2 MP**；
- `suli`、`lili` 成对进入正式数据库，单独语义共鸣各为 **1 MP**；游戏适配只保留轴向长度，不提供整体放大/缩小模式；
- 首版长度灰盒冻结为 1/2/4 格的较短/默认/较长三档；五类元素各自固定截面，长度档不改速度、单位强度或伤害；
- 直接攻击表达最低负荷由三词改为**至少四个有效词＋获准攻击签名**；三词 `N o tawa` 保留为实用档低速控制；
- 上述共鸣不直接改变物理世界，但会产生短时语义回声、显示缺失槽位，并进入学习证据。

## 2. 三层语义契约

每个条目必须分开记录三层：

1. **语言语义域 `language`**：这个词在 toki pona 中可能覆盖的宽泛概念与用法；
2. **游戏学派解释 `magic`**：本世界选取其中哪一部分作为魔法亲和；
3. **运行时默认结果 `world`**：玩家只吟唱这个词时，引擎具体执行什么。

三层之间不能使用等号。例如：

- `telo` 不等于“下坠”；下坠来自世界重力；
- `kon` 不等于“悬浮”；悬浮是 `telo kon` 等配方的世界实现；
- `pona` 不等于“治疗”；
- `pakala` 不等于“伤害”；
- `wawa` 不等于“攻击”或固定倍率；
- `suli` 不等于“放大/增伤”，`lili` 不等于“缩小/减伤”。

UI 应显示“本作中的默认共鸣”，不能显示“`词 = 技能`”。语言语义、游戏解释和物理结果应能分别展开查看。

## 3. 单独施法政策

| 代码 | 含义 | 世界状态 | MP |
|---|---|---|---|
| `CAST_SAFE` | 有安全、确定的单词默认效果 | 可以改变，但无方向、无活体目标、无攻击初速度 | 成功执行后扣除 |
| `CONTEXT_REQUIRED` | 词已识别，但缺少对象、关系或命令信息 | 不产生物理变化；产生短时语义回声与缺失槽位提示 | 扣除条目定义的基础共鸣费 |
| `DISABLED` | 暂不纳入当前章节或规则版本 | 不改变 | 不扣除 |

`CONTEXT_REQUIRED` 不是“错误的 toki pona”。反馈必须是“表达已识别，但当前魔法缺少可执行上下文”，并显示后续可学习的组合槽位。这里扣除的是唤起语义回声的共鸣费，不是答错惩罚；只有成功识别并展示回声时才扣费，解析失败、系统未知或法器故障不扣费。

表中的 MP 是**单词独立调用的默认成本**，不是永久附着在词义上的价格。组合咒语先编译完整 `CastPlan`，再按实际物质、能量、控制、持续与共鸣负荷统一报价；不能简单把每个词的单独成本机械相加，也不能靠增加词数免费增加能量。

所有一词条目共同遵守：

- `direct_attack = false`；直接攻击至少需要四个有效词、完整动作/能量关系和获准攻击签名，词数本身不充分；
- 只能在合法公共施法锚点生效，不得生成在实体碰撞盒或生物体内；
- 默认初速度为零，除非条目本身是无定向的短时场；
- 不锁定活体，不追踪敌人，不凭空决定方向或复杂形状；
- 环境导热、燃烧、重力、流动和碰撞仍正常发生，但不能把这些后果包装成单词攻击技能；
- 生成物受场景显化上限约束，不能进入经济、回复 MP、复制任务物品或形成净能量循环；
- 单词重复、快速切换法器或取消施法不能重复结算物质、能量或退款。

## 4. 魔法功能分类

G-02 只引用 W-01 的八种底层功能：

| ID | 功能 | 单词层用途 |
|---|---|---|
| `MANIFEST` | 显化 | 唤起低信息量的基本物质或短时能量现象 |
| `DRIVE` | 驱动 | 单词层只保留运动钩子；定向推动通常需要组合 |
| `TRANSFORM` | 转化 | 单词层只允许无目标的有限环境变化 |
| `SHAPE` | 构形 | 单词层只给出材料默认形态，不产生精密构件 |
| `STATE` | 赋态 | 单词层只允许合法锚点附近的弱状态变化 |
| `SENSE` | 感知 | 为以后查询材料、移动、损坏或能量留接口 |
| `LIFE` | 生命调节 | 单词层不开放；必须有合法对象与明确状态 |
| `CONDITION` | 条件回路 | 首章仅预留；`la` 从第二章开始教学 |

“攻击、治疗、开门、任务成功”仍然是底层功能在世界里的结果，不是魔法类型。

### 4.1 按魔法类型浏览单词

一个词可以进入多个类型，因为类型描述的是世界功能接口，不是固定词类。粗体表示该词在首章已有安全单词默认效果；普通字表示目前只提供组合钩子，或只在其他类型下单独执行。

| 魔法类型 | 单词 | 单词层可提供的功能 |
|---|---|---|
| 显化 `MANIFEST` | **`telo`** **`seli`** **`kiwen`** **`ko`** **`kon`** | 默认液体、有限热量、硬质物、可塑物、短促空气扰动 |
| 驱动 `DRIVE` | **`kon`** `tawa` `wawa` | 无定向空气脉冲；运动关系；强度/能量投入修饰 |
| 转化 `TRANSFORM` | **`seli`** **`lete`** **`ko`** `kama` `pakala` | 热量变化、冷却、可塑状态；状态转变与失序接口 |
| 构形 `SHAPE` | **`telo`** **`kiwen`** **`ko`** `suli` `lili` | 默认形态；长度修饰只延长或缩短固定截面的轴向构形，不提供运动 |
| 赋态 `STATE` | **`telo`** **`seli`** **`lete`** **`kiwen`** `pona` `awen` `wawa` `suli` `lili` | 液态、热、冷、硬等状态；改善、保持、强度与相对尺度接口 |
| 感知 `SENSE` | **`kon`** `tawa` `kama` `pakala` `wawa` | 为无形介质、运动、变化、损坏、能量查询预留类型钩子；本批不开放独立扫描技能 |
| 生命调节 `LIFE` | `pona` | 只预留改善合法生命状态的组合接口，不开放单词治疗 |
| 条件回路 `CONDITION` | `kama` `awen` | 只预留变化/持续接口；首章不开放自动触发 |

### 7.1 大量组合与“每种方式独特”的实现

本作应鼓励玩家发现组合，但不能为每个字符串手写一个技能。采用两层系统：

1. **规则派生组合**：语言结构、语义钩子、目标和环境共同生成 `CastPlan`；这是绝大多数组合的来源。
2. **精选共鸣配方**：对特别自然、有趣或具有世界观意义的组合增加独特反应、代价、声音、动画或剧情用途，但不能绕过语言和物理规则。

“独特”定义为：两个**语义结构确实不同**的有效组合，至少在下列一个可感知维度不同：

- 材料或能量来源；
- 形状、拓扑或空间关系；
- 运动方式、路径或控制接口；
- 温度、相态或其他状态转换；
- 持续、触发或终止方式；
- 环境交互、可利用对象或副作用；
- MP 结构、维持负担或稳定性。

只换颜色、音效名称或伤害数字不算独特。另一方面，真正的改述、社群变体或不同但等义的表达可以被声明为同一个“改述等价组”，共享基础世界效果；否则游戏会反向教出不存在的语义差别。

每个编译结果生成规范化签名与效果指纹：

```text
combination_signature
= 规范化语法树
+ 词条及其上下文角色
+ 目标/方向绑定
+ 环境与法器能力

effect_fingerprint
= 材料/能量
+ 形状/拓扑
+ 状态转换
+ 运动/路径
+ 生命周期
+ 环境交互
+ 代价与副作用
```

构建检查发现两个非等价签名产生相同指纹时默认失败，要求设计者补足有意义的差异或显式登记等价关系。无效表达、上下文不足表达和危险前置条件失败不需要强行获得独特物理效果。

后续解析不能采用“词序列哈希 → 特殊技能”的黑盒做法。标准流水线是：

```text
分词与结构解析
→ 语义钩子组合
→ 候选动作
→ 上下文与目标绑定
→ 前置条件/安全检查
→ MP 报价与预览
→ 玩家确认或澄清
→ 世界状态转换
→ 学习与物理证据分别记录
```

### 7.2 单长度轴契约：`suli/lili`

`suli/lili` 在语言层仍覆盖物理大小、数量、程度、时长、年龄和重要性等宽语义；“长/短”只是本作元素召唤框架选择的一种可执行解释。为减少模式选择和误操作，本作取消 `SIZE` 整体规模轴，只保留唯一的 `LENGTH` 轴：

- `suli`：从合法锚点沿公开焦点方向延长本次构形；
- `lili`：保持锚点不动，从末端缩短本次构形；
- 每种材料使用固定默认截面；长度词不改变宽度、粗细、密度、温度、压力或单位强度；
- 准星或拖拽只决定延展方向；玩家不再选择“规模/长度”模式，鼠标速度也不转化为动能；
- 默认构形为直线，必须从锚点连续生长；弯曲、分叉、截面变化留给后续词和法器；
- 单独输入 `suli/lili` 只显示固定宽度的长/短无碰撞预览柱；`X li suli/lili` 只生成描述性语义图；
- `suli telo` 不自动等价于 `telo suli`；`telo suli lili` 与重复长度词默认请求澄清。

| 核心 | `suli` 的本世界结果 | `lili` 的本世界结果 | 仍然遵守 |
|---|---|---|---|
| `telo` | 固定直径、沿焦点方向延长的暂态水柱 | 同直径的短水段 | 零初速度；无 `kon/awen` 等稳定关系时受重力坍塌 |
| `seli` | 固定宽度、从合法燃料锚点延长的火舌/热通道 | 同宽度的短火舌或短热脉冲 | 单位温度不增加；需要燃料或额外维持 MP，不是射线 |
| `kiwen` | 固定截面的粗糙长石柱或简单石梁 | 同截面的短石段 | 零初速度；质量线性增加，并承受弯矩、重力和结构应力 |
| `ko` | 固定截面的长泥埂、黏性带或松散物条 | 同截面的短条带 | 黏度和硬度不变；按坡度和重力摊开 |
| `kon` | 固定截面的长空气区域 | 同截面的短气腔 | 压力不增加；无动作关系时不产生定向风，无维持时扩散 |

对于物质，`体积 = 默认截面积 × 长度`，质量随长度近似线性变化；对于火焰、热区和气腔，总能量随保持相同单位强度的长度增加。截面、密度或单位强度如需变化，必须由其他词或法器明确提供，不能暗中塞回 `suli/lili`。

组合按实际工作量报价：

- `suli` 支付新增长度对应的质量、热量、边界和稳定负荷；MP 不足时保留目标档预览并显示缺口、禁止确认，不得静默降档或在施法后随机截断；
- `lili` 的实际物理工作量可因构形较短而降低，但仍支付共鸣与精密控制费，绝不产生负成本或返还已经支付的 MP；
- 后续每秒维持费可随实际长度下降；这是未来负荷减少，不是退款；
- 当前版本不开放对既有物体的后施法伸缩；
- 整条固定截面扫掠体积必须通过碰撞和生物安全检查；遇到障碍或生物安全体积时，预览在最近合法端点截断。

伤害公式不得读取 `suli/lili` 词 ID。延长没有初速度、水压、额外温度或追踪；主动撞击、扫击或投射仍需至少四词的攻击级动作签名。

#### 7.2.1 首版三档与灰盒数值

首版只向玩家提供一个长度选择，不再隐藏第二个整体缩放系统。三档是游戏构形类，不是 toki pona 的三档比较级：

| 构形类 | 表达 | 玩家界面标签 | 长度 | 相对默认 | 修饰词共鸣 |
|---|---|---|---:|---:|---:|
| 较短 | `X lili` | 较短形态｜`lili` | 1 格 | 0.5 | 1 MP |
| 默认 | `X` | 默认形态｜不添加尺度修饰词 | 2 格 | 1.0 | 0 MP |
| 较长 | `X suli` | 较长形态｜`suli` | 4 格 | 2.0 | 1 MP |

“默认”仅表示玩家没有添加尺度修饰词；它不是 `X` 在现实语言中隐含“标准长度”。界面不得把三档画成弱/中/强，也不得显示额外的宽度、大小或伤害滑杆。1 格在灰盒中等于 16 px。

| 元素 | 固定截面宽 | 较短/默认/较长 | 硬上限 | 延展费/格 | 激活 MP（较短/默认/较长） |
|---|---:|---:|---:|---:|---:|
| `telo` | 12 px | 1/2/4 格 | 6 格 | 2 | 6/5/10 |
| `seli` | 8 px | 1/2/4 格 | 6 格 | 2 | 5/4/9 |
| `kiwen` | 16 px | 1/2/4 格 | 4 格 | 2 | 9/8/13 |
| `ko` | 16 px | 1/2/4 格 | 6 格 | 1.5 | 7/6/10 |
| `kon` | 24 px | 1/2/4 格 | 8 格 | 1.5 | 4/3/7 |

激活价按以下方式计算并四舍五入到 0.5 MP：

```text
额外延展费 = max(0, 最终长度格 - 2) × 元素延展费/格
总激活 MP = 核心显化 MP + 修饰词共鸣 MP + 额外延展费
```

`lili` 不退款：较短构形的物理工作量虽较低，仍支付 1 MP 的语义共鸣与精密控制费。普通长度本身不产生每秒维持费；若表达另含 `kon`、`awen` 等状态约束，再由相应状态规则增加维持费。

稳定度统一用下式计算：

```text
S = clamp(base
          + short_bonus × max(0, 1-r)
          - long_penalty × max(0, r-1)^2
          + support - external_load, 0, 1)
r = 最终长度 / 默认长度
```

`S ≥ 0.75` 为稳定，`0.50 ≤ S < 0.75` 显示预警，`S < 0.50` 进入失稳结果。增加无支撑长度不能提高稳定度；失稳只改变坍塌、闪烁、弯折、摊开或扩散方式，不能暗中换算为伤害倍率。

确认施法前必须用同一最终长度驱动渲染与碰撞体，端点误差不超过 1 px，并显示：宽语义说明、本作长度解释、锚点与八方向主轴、最终长度、固定截面、总激活 MP、状态维持费、稳定区间、阻挡对象和释放后行为。障碍可把预览截到最近合法端点，但较长形态至少实现默认长度的 1.25 倍；MP 不足则拒绝该档并显示所需 MP，禁止静默缩短后扣费。

规范数值、元素失稳模式、预览字段、不变量与黄金测试见 [`data/spells/length-profiles.v0.1.yaml`](../../../data/spells/length-profiles.v0.1.yaml)。

### 7.3 三词控制与四词攻击资格

三词 `N o tawa` 是完整、可执行的低速命令：可引水、驱动轻机关、清路或救援，但不锁定活体，不获得攻击级动能。直接攻击至少需要四个**有语义贡献**的词，并命中版本化的攻击签名；这只是必要条件。

| 表达 | 语义贡献 | 本世界默认 |
|---|---|---|
| `telo o tawa` | 水＋命令移动 | 实用档低速水流，非直接攻击 |
| `telo suli o tawa` | 固定截面的长水柱＋移动 | 可让已构成的长水柱进入受控运动；只有通过攻击签名、MP 与安全检查后才进入危险物理 |
| `telo kon o tawa` | 具有 `kon` 性质的凝聚水体＋移动 | 可成为首个稳定飞行水球；同时支付凝聚、运动和维持费 |
| `telo o tawa wawa` | 水＋移动＋有力方式 | 有力水流；必须先在水轮等非战斗任务中使用，碰撞后才由物理产生伤害 |

重复词、无关填充或只有描述没有动作关系的四词表达不获得攻击资格。`N suli o tawa` 改变受控实体长度，`N o tawa wawa` 改变运动方式；两者必须生成不同语义图和效果指纹。更长表达只增加目标、方向、条件或副作用控制，不自动增加总能量。

## 8. 数据条目最小契约

机器可读源文件分为词条源 [`data/spells/single-word-spells.v0.1.yaml`](../../../data/spells/single-word-spells.v0.1.yaml) 与长度数值源 [`data/spells/length-profiles.v0.1.yaml`](../../../data/spells/length-profiles.v0.1.yaml)。词条通过版本化引用取得长度配置；每个单词条目至少包含：

```text
文件级：shared_rules / combination_contract / length_modifier_contract
条目级：id / entry_version / word
language / magic / world
solo_policy / function_tags / semantic_hooks
constraints / misconception_guards / review / tests
world 内：effect_id / effect_zh / cost / anchor / physics / lifetime / geometry（适用时）
```

语义或教学结论改变时提升 `entry_version` 的主版本；只调整 MP、范围或持续时间时提升次版本。发布版必须保留规则版本和存档迁移策略。

首轮至少需要：熟悉 `pu` 传统的使用者、熟悉当代社群用法的使用者、语言教学审阅者、玩法/数值审阅者和实现/QA 审阅者。争议要保留双方解释、采用方案、拒绝方案和复查条件，不能只保存投票结果。

优先审校高风险词：`kon`、`tawa`、`kama`、`pona`、`pakala`、`awen`、`wawa`。

## 10. 可参考的开源构筑方案

完整对照见[《GitHub 咒语构筑参考架构》](../../research/github-spell-construction-references-zh.md)。本项目暂定吸收四个结构原则：

1. 像可组合 glyph 系统一样给成分分配角色，但角色来自 toki pona 结构和语境，不允许任意排列都施法；
2. 像可编程魔法一样先验证程序和代价再改变世界，并提供可解释执行轨迹；
3. 像数据驱动能力系统一样分开能力定义、目标上下文、效果规格和视听反馈；
4. 像开源语言课程一样使用人可审 YAML 作为内容源，经校验后生成运行时资源和练习数据。

## 11. 当前已知未知

- `seli` 单词热源应否允许间接点燃敌人附近燃料，还是首章只允许非战斗场景；
- `lete` 的默认作用介质、最大温差和取消时退款；
- `kiwen` 和 `ko` 的默认视觉材质是否会反向制造“石头/泥”唯一联结；
- `kon` 单词空气扰动是否已经过度收窄其无形/精神语义域；
- 单词显化物的场景衰减速度、存档规则与经济隔离方式；
- `CONTEXT_REQUIRED` 语义回声应持续多久、展示多少候选槽位，以及 1/2 MP 是否会妨碍实验；
- “独特效果”的最低可感知差异应采用哪些维度，精选配方应占全部有效组合的多大比例；
- 三档数值在试玩后是否需要按材料进一步分化，以及什么证据足以允许偏离统一的 0.5/1/2 长度比；
- 首个四词攻击签名需要哪些非战斗迁移证据，才能慢而不变成刷题；
- 社群审阅出现多个都成立的魔法解释时，是并列保留还是按地区/法器分学派。

## 12. 本批验收

- 14 个词的 ID、词形和版本唯一，且 schema 可解析；
- 三层语义全部存在，游戏解释明确标记为非规范性约定；
- 六个 `CAST_SAFE` 条目明确锚点、成本、物理、持续和生成上限；
- 八个 `CONTEXT_REQUIRED` 条目按 1/2 MP 产生语义回声，不产生物理世界变化，也不把缺少上下文说成语言错误；
- 语义不同的有效组合具有不同效果指纹；已登记的改述等价组可以共享指纹；
- 14 个条目全部 `direct_attack = false` 且不能锁定活体；
- `suli/lili` 成对存在，单独共鸣无碰撞；二词长度组合只修改轴向长度，并同步更新物理预算而不直接读写伤害倍率；
- 五类可延展元素的默认长度均为 2 格，较短/较长为 1/4 格，截面在三档间完全不变；
- 预览、渲染与碰撞体共享最终长度且端点误差不超过 1 px；MP 不足拒绝目标档并显示所需 MP，不允许静默降档；
- `telo` 三档激活价为 6/5/10 MP，其余四类分别为 `seli` 5/4/9、`kiwen` 9/8/13、`ko` 7/6/10、`kon` 4/3/7；
- “默认形态”只表示未添加尺度修饰词；教学与 UI 不把它包装成 toki pona 的标准长度，也不把三档包装成弱/中/强；
- 任意直接攻击签名至少四个有效词；四词长度不自动授予攻击，`telo o tawa` 保持非攻击档；
- UI 和文档中不存在 `pona=治疗`、`pakala=伤害`、`wawa=攻击`、`kon=悬浮`、`telo=下坠` 等式；
- 所有外部项目只借鉴机制与架构，代码和资产使用前另做许可证审查。
